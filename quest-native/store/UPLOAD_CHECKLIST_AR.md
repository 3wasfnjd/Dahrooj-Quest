# قائمة رفع «دحروج» على متجر Meta Horizon — خطوة بخطوة

- كل ملف تحتاجه موجود في هذا المجلد `quest-native/store/`.
- كل خطوة فيها مربع ☐، علّم عليه إذا خلّصتها.
- الخطوات اللي تحتاج النظارة نفسها مجموعة في آخر الملف.

> **قاعدة ثابتة:** أي سرّ (مفتاح التوقيع، كلمة مروره، App Secret) **لا يُلصق في المحادثة أبدًا** ولا في أي ملف داخل المستودع. مكانه الوحيد: GitHub Secrets، ونسختك الاحتياطية الخاصة.

---

## ١) حساب المطوّر والمنظمة والتطبيق

- ☐ ادخل على https://developers.meta.com/horizon بحساب Meta، وفعّل التحقق بخطوتين.
- ☐ أنشئ **منظمة (Organization)** باسم `Aboden Games`. التطبيق ينسجّل تحت المنظمة.
- ☐ بما إن التطبيق مدفوع، كمّل في لوحة التحكم:
  - ☐ **حساب الأرباح (Payout)**: بيانات البنك.
  - ☐ **البيانات الضريبية (Tax)**.
  - بدونها ما يقبل المتجر سعرًا.
- ☐ اضغط **Create New App** واختر منصة **Meta Horizon Store / Quest** (تطبيق Android للنظارة)، واكتب الاسم: `Dahrooj` (أو `دحروج — Dahrooj`).
- ☐ تأكد إن اسم الحزمة اللي بترفعه هو `com.abodengames.dahrooj`. هذا الاسم يثبت مع التطبيق للأبد.

## ٢) رقم التطبيق والسر (App ID و App Secret)

- ☐ من لوحة التحكم: **تطبيقك ← Development ← API**. (رسالة الخطأ في سير العمل تشير لنفس المكان: «Developer Dashboard > your app > API».)
- ☐ انسخ **App ID**، وهو رقم.
- ☐ انسخ **App Secret**. هذا سرّ: لا ترسله لأحد، ولا تلصقه في المحادثة.

## ٣) مفتاح التوقيع الدائم (Keystore): أنت فقط اللي تسوّيه

> - **الجلسة (Claude) ما تنشئ المفتاح، ولا تشوفه، ولا تحفظه، ولا ترفعه للمستودع.**
> - المفتاح هو «هوية» التطبيق: كل تحديث بعدين لازم ينوقّع **بنفس المفتاح بالضبط**. لو ضاع، ما تقدر تحدّث اللعبة أبدًا، وتضطر تنشئ تطبيقًا جديدًا من الصفر.

**شروط المفتاح.** سكربت البناء يرفض أي مفتاح ما يطابقها:

- نوعه **PKCS12**.
- **كلمة مرور وحدة** للملف وللمفتاح نفسه (لا تحط كلمتين مختلفتين).
- مدته طويلة، ونوعه RSA 4096.

**طريقة إنشائه بدون كمبيوتر: تطبيق Termux على جوال أندرويد**

1. ☐ نزّل **Termux** من F-Droid أو GitHub، لأن نسخة Google Play قديمة.
2. ☐ اكتب فيه:
   ```
   pkg update && pkg install openjdk-17
   keytool -genkeypair -v -storetype PKCS12 -keystore dahrooj-release.p12 \
     -alias dahrooj -keyalg RSA -keysize 4096 -validity 36500 \
     -dname "CN=Aboden Games, O=Aboden Games"
   ```
   - بيطلب كلمة مرور. اختر كلمة قوية واكتبها مرتين.
   - إذا سألك عن كلمة مرور للمفتاح، اضغط Enter عشان تكون نفسها.
3. ☐ حوّل الملف لنص Base64:
   ```
   base64 -w 0 dahrooj-release.p12 > dahrooj-release.b64
   termux-setup-storage
   cp dahrooj-release.p12 dahrooj-release.b64 ~/storage/downloads/
   ```
4. ☐ **النسخة الاحتياطية، قبل أي شي ثاني:**
   - انسخ `dahrooj-release.p12` **وكلمة المرور** لمكانين آمنين ومنفصلين، مثل مدير كلمات مرور وفلاشة أو سحابة مشفّرة.
   - لا تحطه في GitHub كملف، ولا ترسله في واتساب أو بريد عادي.

**بديل:** GitHub Codespaces من المتصفح. فيه طرفية يتوفر فيها `keytool` بنفس الأوامر، وبعدها تنزّل الملف لنسختك الاحتياطية.

**تنبيه:** سير العمل `signing-key-bootstrap.yml` الموجود في المستودع خاص بنسخة الويب (أسراره `ANDROID_*`)، **ما يخدم النسخة الأصلية** (`DAHROOJ_*`). لا تشغّله لهذا الغرض.

## ٤) أسرار GitHub

افتح المستودع على GitHub ← **Settings ← Secrets and variables ← Actions ← New repository secret**، وأضف الخمسة هذي، كل واحد باسمه بالضبط:

| الاسم | القيمة |
|---|---|
| `META_APP_ID` | رقم التطبيق من الخطوة ٢ |
| `META_APP_SECRET` | سرّ التطبيق من الخطوة ٢ |
| `DAHROOJ_KEYSTORE_B64` | محتوى ملف `dahrooj-release.b64` **كامل**: سطر واحد طويل |
| `DAHROOJ_KEYSTORE_ALIAS` | `dahrooj` (أو الاسم اللي كتبته بعد `-alias`) |
| `DAHROOJ_KEYSTORE_PASSWORD` | كلمة مرور المفتاح |

- ☐ بعد ما تضيفها، **احذف** ملف `.b64` من مجلد التنزيلات في الجوال، وخلّ نسختك الاحتياطية المشفّرة فقط.
- ☐ **انتبه:** بعد إضافة `META_APP_ID` تصير كل بناءات GitHub (حتى اللي تطلع تلقائيًا مع كل push، واللي رسالتها فيها `[release]`) نسخ متجر:
  - موقّعة بمفتاحك.
  - فيها فحص الشراء: النسخة تقفل إذا الحساب ما يملك اللعبة.
  - لتجربة APK بالتحميل الجانبي (sideload)، شغّل سير العمل مع خيار `sideload_test`، لأنه يتجاهل الأسرار ويستخدم مفتاح التجربة.

## ٥) كيف يرفع GitHub Actions البناء لقناة ALPHA

سير العمل: `.github/workflows/quest-native-apk.yml`، واسمه في تبويب Actions: **«Quest Native APK · النسخة الأصلية»**.

**تشغيله يدويًا (workflow_dispatch):**

- **Actions ← Quest Native APK ← Run workflow**، واختر الفرع اللي فيه آخر نسخة.
- **تنبيه:** زر «Run workflow» يظهر في واجهة GitHub بس إذا ملف سير العمل موجود في الفرع الافتراضي `main`. حاليًا هو موجود في فرع `quest-native` فقط، فلازم يندمج في `main` أولًا، أو يتشغّل عن طريق الـAPI.

**الخيارات في نافذة التشغيل:**

- `publish`: ينشر APK كإصدار تجريبي عام (pre-release) على GitHub. **لا تفعّله** لبناء المتجر.
- `sideload_test`: بناء بمفتاح التجربة، بدون فحص الشراء، للتجربة الجانبية فقط. **لا تفعّله** مع الرفع.
- `upload_alpha`: **فعّله** للرفع على قناة ALPHA.
- `age_group`: `TEENS_AND_ADULTS` (الافتراضي، والمقترح للبداية) أو `MIXED_AGES`. التفاصيل في `listing_ar.md`.

**وش يصير بعدها، بالترتيب:**

1. يبني اللعبة بـGodot 4.6.3 ويشغّل كل الاختبارات.
2. يفك مفتاحك من `DAHROOJ_KEYSTORE_B64` ويتأكد من كلمة المرور والاسم المستعار (alias).
   - يرفض المفتاح إذا كلمة مرور المفتاح تختلف عن كلمة مرور الملف.
3. يكتب `META_APP_ID` داخل اللعبة، فيتفعّل **فحص الشراء** (`scripts/core/store_entitlement.gd`).
4. رقم الإصدار (version code) = رقم تشغيل سير العمل، فيزيد دايمًا تلقائيًا.
5. يتحقق من الـAPK:
   - التوقيع بشهادتك.
   - arm64 فقط.
   - targetSdk 34.
   - Quest 3 و3S.
   - فئة VR.
6. يرفض الرفع إذا:
   - `META_APP_ID` أو `META_APP_SECRET` ناقص.
   - البناء موقّع بمفتاح التجربة العام.
7. ينزّل أداة Meta الرسمية `ovr-platform-util` من oculus.com، ويشغّل:
   ```
   upload-quest-build --app-id … --app-secret … --apk … --channel ALPHA --age-group … --notes "Build N from <commit>"
   ```
8. الـAPK وتقرير التحقق (`apk-report.txt`) يكونون في **Artifacts** صفحة التشغيل.
   - ☐ افتح `apk-report.txt` وتأكد إن الأذونات بس اللي في `DATA_USE.md`: `RENDER_MODEL` و`USE_ANCHOR_API` و`USE_SCENE` (مع أذونات OpenXR الأساسية).

> - رفع البناء **ما يعني** إرسال التطبيق للمراجعة.
> - الإرسال للمراجعة يصير من لوحة التحكم فقط (الخطوة ٨).

## ٦) التجربة على قناة ALPHA

- ☐ لوحة التحكم ← **Release Channels ← ALPHA**: تأكد إن البناء ظاهر برقم الإصدار الصحيح.
- ☐ أضف نفسك وأي مجرّب بإيميل حساب Meta حقه.
- ☐ اقبل الدعوة، وبعدها تلقى اللعبة في مكتبة النظارة. نزّلها من هناك، مو بالتحميل الجانبي.
- ☐ جرّب «أشياء ما تتسوّى إلا على النظارة» (آخر الملف).
- ☐ خلّص التجربة **قبل** الإرسال للمراجعة. الإرسال يوقف الصلاحيات المؤقتة لمزايا المنصة إلى أن تنتهي مراجعة «Data Use Checkup».

- **مقترحات الإعدادات:**
  - التصنيف (Genre): Casual وArcade وSports.
  - الراحة (Comfort): **Comfortable**.

  - الإنترنت: غير مطلوب.

## ٨) التصنيف العمري والسعر والإرسال

- ☐ **IARC:** عبّ الاستبيان من «ملاحظات استبيان التصنيف العمري» في `listing_ar.md`.
  - الملخص: عنف كرتوني خفيف (فرقعة شخصيات جلي)، وبدون محادثة، ولا مشتريات، ولا جمع بيانات، ولا قمار.
- ☐ **Data Use Checkup:**
  - لا تطلب أي ميزة من مزايا المنصة (التفاصيل في `DATA_USE.md`).
  - ضع رابط سياسة الخصوصية.
- ☐ **السعر:** المقترح للإطلاق **4.99 دولار**.
  - تقدر تسوي خصم إطلاق بعدين من لوحة التحكم.
  - يحتاج حساب الأرباح والبيانات الضريبية من الخطوة ١.
- ☐ **الإرسال:** **Submission**:
  - تأكد إن كل الأقسام عليها علامة خضراء.
  - عالج التحذيرات.
  - اضغط **Submit for Review**.
- المراجعة تاخذ تقريبًا **أسبوع إلى أسبوعين**. لا تحدد موعد إطلاق قبل ما يمرّ أسبوعان على الأقل.
- بعد القبول: تختار تطلقها فورًا أو تحدد تاريخًا.

## ١٠) أشياء ما تتسوّى إلا على النظارة (أنت فقط)

- ☐ تنزيل البناء من قناة ALPHA وتشغيله.
- ☐ قياس الأداء:
  - استخدم **OVR Metrics Tool** (متوفر من متجر Meta) لقياس الإطارات في كل نمط.
  - المطلوب 72 ثابتة.
- ☐ جلسة لعب 15 دقيقة على الأقل بدون انهيار، وراقب الحرارة.
- ☐ الواقع المختلط:
  - مع إعداد غرفة.
  - بدون إعداد غرفة.
  - مع رفض إذن «بيانات المشهد».
- ☐ فتح قائمة Meta وسط اللعب والرجوع، وإعادة التوسيط.
- ☐ تبديل العربي والإنجليزي من القائمة.
- ☐ **لقطات واقع مختلط حقيقية** وتسجيل الفيديو الدعائي:
  - زر Meta ← الكاميرا ← التقاط صورة / تسجيل.
  - انقلها للجوال من تطبيق Meta Horizon.
- ☐ إنشاء مفتاح التوقيع وحفظ نسخته الاحتياطية (الخطوة ٣). **هذا عليك وحدك.**
