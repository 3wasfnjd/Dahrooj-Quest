# دحروج — APK محلي تجريبي

11 أكتوبر 2026. جرى بناء حزمة أندرويد فعلية موقعة تضم ملفات اللعبة. تفتح اللعبة في **Meta Quest Browser** من خدمة محلية داخل النظارة. ليست نسخة Unity ولا تطبيق XR مستقلًا عن المتصفح. أفاد المالك بأن **v1 اشتغلت على النظارة** وأن كل شيء سليم باستثناء سواد خامات أعمدة الإنارة والفوانيس والكراسي في VR. النسخة الحالية **v2** تصلح سببًا أُعيد إنتاجه في الاختبار؛ **لم يختبرها المالك على النظارة بعد**. لم يؤكد التقرير السابق إيقاف Wi-Fi.

## إصلاح الخامات في v2

صور الألوان موجودة داخل ملفات GLB، وليست ملفات ناقصة من الحزمة. يُخرج `GLTFLoader` الصور المضمّنة إلى عناوين `blob:`، ثم يقرأها `ImageBitmapLoader` بواسطة `fetch()`. كانت سياسة CSP تسمح بـ`blob:` في `img-src` فقط، بينما يخضع `fetch()` إلى `connect-src`. كان تحميل الهندسة ينجح وتحميل الصور يُحجب، ثم يعيد المحمّل خامة دون `map`. تمر هذه القيمة إلى شيدر مجسمات العالم الذي يقرأ خريطة اللون، ما يفسر السواد المبلغ عنه.

أُضيف `blob:` إلى `connect-src` في خادم APK وفي `vercel.json`، دون السماح بعنوان خارجي. لم تتغير الشيدرات أو الإضاءة أو ألوان المجسمات. جميع ملفات اللعبة الـ119 داخل v2 مطابقة لملفات v1 حرفيًا. تبقى الحزمة والمنفذ وشهادة التوقيع نفسها، ويرتفع رقم البناء إلى 2.

اختبار جديد يستخدم `GLTFLoader` الفعلي لقراءة **المجسمات الثمانية** من ملفات الحزمة عبر خادم Java الفعلي وسياسة CSP الفعلية. يختبر فك الصور إلى `ImageBitmap`، أبعادها، تعريف sRGB، ووجود ألوان في بكسلاتها. قبل الإصلاح: فشلت الصور الثماني مع ثماني مخالفات `connect-src` لعناوين blob. بعده: نجحت الصور الثماني دون مخالفة. بقي طلب HTTPS خارجي ممنوعًا بالسياسة قبل وصوله إلى الشبكة. هذا يثبت إصلاح تحميل الصور، ولا يُعد اختبارًا لرسم العينين أو أداء النظارة.

الأدلة: [الفشل قبل الإصلاح](evidence/local-apk/v2/materials-before-fix.json)، [النجاح بعده](evidence/local-apk/v2/browser-report.json)، [تقرير بناء v2](evidence/local-apk/v2/build-report.json). الاختبار القديم اقتصر على صفحة الدخول والتحقق من الملفات؛ لم يكن يشغّل تحميل صور GLB المؤجل إلى العالم في VR.

## محتويات النسخة

- الحزمة `com.abodengames.dahrooj.localtest`، الإصدار `0.2-local-test`، رقم البناء `2`.
- المصدر `95dac398081d6f0c047db3cb4e7fde4efd42fd27`، بناء اللعبة `c19a44cfa3cff2`.
- APK حجمه **6,537,028 بايت**، يحتوي **119 ملفًا** للعبة بحجم إجمالي غير مضغوط **11,652,991 بايت**.
- ملفات الرسم والفيزياء والأنماط والقوائم لم تتغير. الملفات الـ118 غير `sw.js` مطابقة للبناء السابق حرفيًا.
- استُبدل `sw.js` داخل نسخة APK فقط بعامل خدمة لا ينزّل تحديثات ولا يحتاج زيارة سابقة لتخزين اللعبة. الملفات تأتي من APK في كل تشغيل. لا يمسح العامل الجديد localStorage أو IndexedDB.
- يستمع الخادم على `http://127.0.0.1:48189/` فقط، ولا يفتح منفذًا على شبكة Wi-Fi. المنفذ ثابت للحفاظ على عنوان الحفظ.
- إذن Android المسمى `INTERNET` مطلوب لمقبس loopback المحلي. الغلاف لا يحتوي عميل تنزيل أو تحليلات أو تحديثات. متصفح Meta تطبيق منفصل؛ لا نتحكم في اتصالاته الداخلية.

## تجربة النظارة المطلوبة

1. ثبّت `Dahrooj-local-test-v2.apk` **كتحديث فوق v1 دون حذفها**. عند توفر حاسوب متصل بالنظارة: `adb install -r Dahrooj-local-test-v2.apk`. إذا كانت اللعبة أو خدمتها تعمل، أوقفها من التطبيق ثم افتح اللعبة مجددًا بعد التحديث.
2. **قبل أول تشغيل، أوقف Wi-Fi.** لا تفتح الموقع المستضاف بغرض تخزين اللعبة مسبقًا.
3. افتح «دحروج · محلي» ثم «تشغيل اللعبة». يفترض أن يفتح متصفح Quest شاشة اختيار VR وMR.
4. في VR افحص ألوان أعمدة الإنارة والفوانيس والكراسي، ثم جرّب الوضعين والأنماط والقوائم. تحقق من بقاء إعداداتك وتقدمك السابقين. اخرج وأعد التشغيل للتحقق من الحفظ، ثم أعد تشغيل النظارة مع بقاء Wi-Fi مغلقًا وجرّب مجددًا.
5. اترك خدمة دحروج تعمل أثناء اللعب. أوقفها من زر التطبيق أو إشعاره بعد الانتهاء. إذا أوقفها النظام، أعد تشغيل اللعبة من التطبيق.

إذا لم يفتح المتصفح آليًا، أدخل العنوان المحلي أعلاه في **متصفح النظارة نفسها** أثناء عمل الخدمة. إذا لم تُفعّل أزرار XR أو توقفت الخدمة عند الدخول إلى اللعب، فهذا فشل في اختبار الجهاز يجب توثيقه؛ لا يُعد فتح الموقع المستضاف نجاحًا لهذا الاختبار.

الحفظ منفصل عن حفظ الموقع السابق لاختلاف عنوان الأصل. يبقى داخل مساحة تخزين ذلك العنوان في المتصفح. لا تمسح بيانات المتصفح إذا أردت الاحتفاظ به. لا ترحّل هذه النسخة تقدم الموقع تلقائيًا.

## إعادة البناء

المتطلبات: Python 3، JDK 21، Android SDK Platform 34 وBuild Tools 36.0.0. أدوات البناء 36 تعالج عدم توافق D8 القديم مع مخرجات JDK 21؛ يبقى `minSdk=32` و`targetSdk=34` و`compileSdk=34`.

```sh
npm ci
npm run build
python quest-package/local/build.py --sdk "$ANDROID_SDK_ROOT" --jdk "$JAVA_HOME"
npx playwright install chromium --only-shell
node quest-package/local/test-browser.mjs
```

يستخدم اختبار المتصفح `JAVA_HOME` ويقبل `PLAYWRIGHT_CHROMIUM_EXECUTABLE` لمتصفح مثبت. يتطلب البناء أولًا؛ يختبر الملفات نفسها المجمّعة داخل APK عبر خادم Java نفسه، مع منع طلبات صفحات اللعبة إلى الخارج.

يمكن عزل مجلد التجهيز بإضافة `--work-dir /مسار/المستودع/quest-package/generated/local/work-v2` للبناء، وتمرير المسار نفسه عبر `APK_TEST_WORK` لاختبار المتصفح. يقبل الاختبار `APK_BROWSER_REPORT` لتسمية تقرير تجربة قبل الإصلاح دون الكتابة فوق تقرير الإصدار القديم. ملف اختبار الصور يُجمع في الذاكرة ويُحقن في الاختبار فقط؛ لا يدخل APK.

المخرجات داخل `release/`: APK وبصمته وتقريرا البناء والمتصفح. مفتاح **التجربة** في `quest-package/generated/local/local-test.keystore`، اسمه `androiddebugkey` وكلمة مروره العامة `android`. ليس مفتاح إصدار تجاري؛ احتفظ به محليًا لإعادة تثبيت تحديث تجربة فوق الحزمة نفسها. لا ترفعه إلى Git ولا تستخدمه للإصدار النهائي.

إعادة بناء تحديث v2 تحتاج مفتاح التجربة الأصلي؛ يتوقف البناء إذا فُقد أو اختلفت الشهادة، بدل إنشاء توقيع جديد لا يمكن تثبيته فوق النسخة الموجودة. بصمة شهادة التجربة SHA-256: `4c8cebcce50fff6b2fddafe9d44b9de9882491d8a8fac98fa9c22fb790829967`.

بصمة APK لهذا التسليم v2: `c5220f72357e09337141cca3b340e6d5dbd634e425eb9bd59929299417f25095`. بقي APK v1 السابق دون تغيير.

المصدر والاختبارات في `quest-package/local/`. مهمة Bubblewrap القديمة الخاصة بالأصل المستضاف مسار مختلف ولا تبني هذه الحزمة. مصدر الحزمة لا يحتاج Gradle أو Unity أو حساب Unity.
