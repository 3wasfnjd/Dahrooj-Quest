# إدارة دحروج من iPhone فقط

لا تتطلب الخطوات حاسوبًا شخصيًا أو Node أو JDK محليًا. الأدوات تُثبت في GitHub Actions. لا تنشر أي سر في محادثة أو ملف Git أو issue.

## وضع الإعداد الحالي

المستودع الجديد مخصص للعبة؛ الأصل الدائم ومعرّف Meta غير مضبوطيْن في `quest-package/app-config.json` عمدًا. تكامل Vercel المتاح في جلسة الإنشاء رفض النطاق المطلوب بـ403 ولم يمنح وصولًا صالحًا للمشروع. يلزم ربط حساب/فريق Vercel الصحيح أو إدخال إعدادات Actions أدناه. لا يُستخدم نطاق قديم أو مشروع غير متعلق بدحروج.

## HTTPS أولًا

من متصفح الهاتف، أنشئ مشروع Vercel جديدًا مربوطًا بـ`3wasfnjd/Dahrooj-Quest`. اختر Vite ومجلد الجذر الحالي. احتفظ بالنطاق الرئيسي الدائم، سواء نطاق المشروع الثابت أو نطاقًا مملوكًا لك. يجب أن يكون التطبيق في جذر الأصل، لا مسار مستودع فرعي. لا تغيّر `APP_ORIGIN` بعد ربط APK دون خطة تحديث مدروسة.

من GitHub → Settings → Secrets and variables → Actions أضف متغيرات Repository:

| المتغير | القيمة |
|---|---|
| APP_ORIGIN | أصل HTTPS الحقيقي، بلا مسار أو شرطة مائلة أخيرة |
| VERCEL_ORG_ID | معرّف الفريق/الحساب الذي يملك مشروع اللعبة الجديد |
| VERCEL_PROJECT_ID | معرّف مشروع دحروج الجديد فقط |
| META_APP_ID | معرّف تطبيق Quest الجديد من لوحة Meta، لا اسم الحزمة |
| ANDROID_CERT_SHA256 | بصمة شهادة الإصدار الدائمة، تُضاف بعد إنشائها/استعادتها |

أضف Secret `VERCEL_TOKEN` محدودًا للفريق المناسب. أنشئ GitHub Environments باسم `production` و`quest-release`، واجعل الكتابة والنشر من `main` فقط. لا تسمح لفروع غير موثوقة بالوصول لأسرار التوقيع. استخدام Reviewers اختياري وفق فريقك، وليس متطلبًا لتثبيت أدوات على الهاتف.

نفّذ **Deploy HTTPS**. المهمة تفحص أصل النشر، تختبر وتبني، تنشئ deployment محددًا، تتحقق من manifest ثم تروّج نفس deployment إلى الإنتاج. عند توفر الشهادة تولّد DAL قبل البناء وتتحقق منه بعد النشر. لا تنقل المشروع إلى مستودع legacy. راقب سجل الأخطاء؛ رابط عشوائي مؤقت لا يُعتمد أصلًا للـAPK.

## الشهادة الدائمة

إذا كان تطبيق `com.abodengames.dahrooj` منشورًا سابقًا، **استخدم شهادة تحديثه الأصلية** بعد تأكيد Meta للهوية. لا تنشئ شهادة بديلة. قبل الإصدار الأول لتطبيق جديد، تأكد من توفر اسم الحزمة في لوحة Meta ثم اختر أحد المسارين:

- شهادة موجودة: أضف `ANDROID_KEYSTORE_BASE64` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD` إلى GitHub Secrets، وأضف البصمة العامة الصحيحة إلى Variables.
- لا توجد شهادة منشورة: مهمة **Create permanent signing key** تولّدها في السحابة مرة واحدة وترفض الكتابة فوق سر مفتاح موجود. أدخل أولًا كلمات سر مستقلة وقوية في Secrets للأسماء السابقة ما عدا BASE64، وأضف `KEY_BACKUP_PASSWORD` بطول 20 حرفًا على الأقل.

مسار الإنشاء الأول يحتاج Secret مؤقتًا `SIGNING_ADMIN_TOKEN`: GitHub fine-grained token محصور بهذا المستودع بصلاحيات Repository secrets وVariables للكتابة وMetadata للقراءة؛ يستخدم gh لتخزين المفتاح مباشرة دون طباعته. لا يُمنح للنشر العادي. شغّل المهمة من Actions على `main`. بعد نجاحها، نزّل Artifact `permanent-signing-backup-encrypted` من iPhone واحفظ نسختين من `signing-backup.gpg` في موقعين آمنين، واحفظ كلمة فك التشفير منفصلة. الملف المشفر ينتهي من GitHub بعد 90 يومًا؛ ليس GitHub نسخة احتياطية دائمة. احذف `SIGNING_ADMIN_TOKEN` بعد النجاح. لا تعِد توليد المفتاح لتجاوز مشكلة كلمة المرور.

أعد تشغيل **Deploy HTTPS** ليُنشَر `/.well-known/assetlinks.json` ببصمة الشهادة نفسها. التحقق يشترط HTTPS وHTTP 200 ومحتوى JSON صحيحًا بلا تحويل إلى موقع آخر، مع `com.abodengames.dahrooj` والبصمة المطابقة وعلاقة `delegate_permission/common.handle_all_urls`. لا نكتب ملفًا وهميًا ببصمة صفرية.

## APK من Actions

من Actions → **Quest APK · بناء حزمة كويست** → Run workflow، اختر `main` وأدخل `version_code` أكبر من أي نسخة قُدمت سابقًا. تُجري المهمة الاختبارات والبناء والتحقق من الأصل وDAL والمصادر الرسمية الحديثة، وتثبت Node وJava وAndroid SDK وMeta Bubblewrap، وتستعيد الشهادة وتولد مشروع Android بوضع `immersive`، ثم تبني وتوقّع وتفحص APK الفعلي.

مخرجات النجاح: `dahrooj-quest.apk` و`dahrooj-quest.apk.sha256`، وتقارير apksigner وaapt واختبارات وحجم الحزمة وملخص عربي. لا تكفي علامة توليد Android للنجاح؛ أي فشل DAL أو بصمة أو صلاحيات أو SDK أو ABI أو توقيع يُوقف المهمة. احتفظ بأرشيف إصدار لكل نسخة وتقرير اختبار النظارة المرتبط بـSHA وversionCode.

الخط الأساسي المؤرخ 2026-10-08: minSdk32 / targetSdk34 / compileSdk34، توقيع v2، headtracking مطلوب، installLocation auto، non-debuggable، أجهزة Quest2/3/3S. `check-meta-policy.mjs` يجلب الوثائق قبل التغليف ويتوقف إذا كان التدقيق أقدم من 30 يومًا أو تعذر جلب المصدر. الجلب ليس موافقة آلية على نص السياسة؛ راجع التغييرات وجدول VRC قبل كل إصدار.

## اختبار الجهاز وإصدار المتجر

ابدأ باختبار HTTPS داخل Quest Browser. لا تدّع اختبار APK قبل تثبيته وتشغيله فعلًا على نظارة؛ يمكن إدارة قنوات اختبار Meta والملفات من متصفح الهاتف عند تفعيل حساب المطور والتطبيق. إذا رفضت Meta الملف فاحتفظ برسالة الرفض وأصلحها في هذا المستودع. لا توجد مهمة رفع تلقائي إلى Production في Meta Horizon Store.

للتطوير المتقدم استخدم GitHub Codespaces اختياريًا عبر المتصفح. تغيير كود واختبار CI وإدارة الأسرار وتنزيل APK لا يتطلب Codespaces أو حاسوبًا شخصيًا.
